# 多 Git 仓库项目与统一需求工作区

一个业务项目可以登记一个 Git 根目录，也可以登记包含多个独立 Git 仓库的父目录。父目录模式先扫描并勾选仓库及共享说明文件；系统保留各仓库相对目录，不要求父目录初始化 Git。

## 在 Windows 11 中使用

1. 进入“项目登记”，选择“多 Git 仓库父目录”，填写如 `D:\code\business` 的本机绝对路径，点击“扫描 Git 仓库”。
2. 勾选项目仓库及需要带入的共享 `AGENTS.md`、`README.md` 等说明文件，选择已构建的运行镜像，保存业务项目。扫描只列出有提交记录的 Git 根目录；路径变化后需重新扫描。
3. 保存该项目的运行配置，选择 Agent CLI，并填写各仓库的构建、验证命令，或填写在父目录运行的统一验证命令。命令使用容器内的 Linux 程序和相对路径，Windows 主机路径只用于登记源码与挂载。项目容器使用同一个镜像，需要包含所有候选仓库所需工具。
4. 新建一个业务需求，关联该业务项目，勾选本次候选仓库。创建工作区、执行环境预检、启动环境后，按已有开发流程分析、确认范围和开发。
5. 开启流程时可选择“按固定运行配置逐仓库验证”。工作台在对应仓库目录分别运行命令，执行记录展示每个仓库的退出码与输出；全部候选必须通过，才能进入模型评审。
6. 继续完成自审、概要设计和测试材料。需要完整代码交付包时，在“跨项目交付”关联这个业务需求即可；无需为每个子仓库另建需求。还可关联其他业务项目的需求进行联合交付。

业务需求只录入一次，从该业务项目选择本次候选仓库。创建需求后仓库集合固定；分析和人工范围确认确定本轮具体改动，未改动的候选仓库仍可提供上下文。需要另一组候选时创建新需求。不同需求的代码和 Agent HOME 独立。

工作区首次准备时以各仓库的 `HEAD` 建立独立副本和 `req/<需求 ID>` 分支，源仓库未提交的改动不自动带入。登记的仓库清单固定；需要增补项目仓库时重新登记父目录，已有需求保持其原有集合。

统一工作区示例：

```text
/workspace/project/          # Agent CLI 的工作目录
  AGENTS.md                  # 登记时明确选中的共享说明
  order-service/.git/         # 独立导出的 Git 仓库与需求分支
  payment-service/.git/
```

普通开发可以在一次会话中跨仓库修改。分析、模型评审和材料生成复制全部候选到独立只读环境。整体代码摘要覆盖全部候选与共享文件；任一仓库变化均使旧代码确认失效。源码复制不携带原始远程认证、hooks 或外部 Git 对象目录。

项目运行配置使用一个包含各仓库所需工具的镜像，并可分别配置各仓库的构建和验证命令。命令在对应的仓库目录运行，返回独立退出码和输出摘要；统一流程仍只在实际验证全部通过后进入评审。共享父目录也可以提供统一验证脚本。

代码差异保留仓库路径前缀。完整交付包包含各仓库源码、原始提交和独立补丁；备份保存各仓库独立 Git 元数据及共享文件基线，恢复后保持相对布局，不重放任务。

数据库迁移 `0010` 为项目增加仓库和共享文件清单、为需求保存所选仓库。已有单仓库项目和需求清单为空，继续沿用原有流程。旧 `0005`–`0009` 备份恢复时补齐空清单。

扫描只读取本机目录和 Git 元数据，不调用模型、不构建镜像。目录使用本机绝对路径，支持 Windows 中文和空格路径；拒绝越界路径、符号链接/junction、仓库嵌套、重复或大小写冲突。未勾选仓库和未选择的父目录文件不会复制到 Agent 环境。每个业务项目最多 16 个仓库，扫描深度最多 4 层；单个共享文件最多 1 MiB，源码复制合计最多 100 MiB。

## 验证与复现

```text
python poc/run_unit_tests.py
npm run --prefix web build
python poc/verify_multi_repo.py --root .local-data/multi-repo-acceptance
```

真实容器验收需先构建 `agent-workbench-m1:local`，并安装浏览器验证依赖。脚本的默认 Chromium 路径是 `/usr/bin/chromium`；其他安装位置通过 `--chromium` 指定。`--root` 必须是尚不存在的专用测试目录。

脚本通过网页登记父目录、配置命令并创建一个业务需求，使用实际兼容封装 CLI 的标准输入与 JSON 输出传输执行受控改动；服务、逐仓库测试和只读隔离均在真实 Docker 中运行。分析、评审及概要设计使用明确标记的离线固定报告，输出 `model_inference=false`。报告和桌面/手机截图保存在指定测试目录；脚本停止测试资源并只移除其自行创建的镜像标签。

回归覆盖旧单仓库流程、`0009`→`0010` 数据升级、旧版备份恢复、并行需求隔离、Git 元数据边界、共享基线、各仓库独立二进制补丁及完整交付包。逐仓库验证缺少任一候选记录时，流程拒绝进入模型评审。
