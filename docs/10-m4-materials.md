# M4 材料与反馈闭环

- 版本：0.4.0；日期：2026-10-24。
- 基线：M3 PR #3 已合并到 main（`6a566ed`）。

M4 在已完成自审的 M3 轮次之后开启独立材料轮次，不改变历史 M3 模板。材料轮次固定需求修订、代码摘要及自审来源。

## 流程

概要设计生成/修订 → 主管评审登记 → 性能测试判断 → 功能测试单 → 条件性能测试单 → 实际测试结果登记 → 材料阶段验收。

- 文档及测试用例定义保存不可变版本；人工编辑创建新版本，不覆盖 Agent 结果。
- 主管决定绑定概要设计版本；记录评审人、时间、意见与证据引用，由开发者登记，不代替主管本人认证。
- 性能判断为 UNDECIDED / REQUIRED / NOT_REQUIRED；未决不能跳过，不需要时保存原因，需要时必须有指标和性能用例。
- 测试材料生成不会生成测试执行记录。实际结果另存执行人、时间、环境、逐项实际结果及证据引用。
- 文档或代码变化使引用旧版本的评审及测试结果失效，原记录保留。
- Bug 可在明确沿用原范围时开启开发修复轮次；需求或架构变更新建需求修订并返回分析。文档意见要求生成/编辑新版本后重新评审。
- 导出带版本、摘要和当前有效性说明的材料包。材料阶段验收与 M5 全项目交付分开。

## 实现边界

继续使用单机 API、持久队列及 Runner。生成文档的模型仅访问独立只读代码副本，正式材料保存在控制数据库，导出文件位于 Agent 未挂载的私有目录。当前模型接入与 M3 相同，在线生成仍需服务可用；验收替身与真实调用分别记录。

## 本机使用

按 [工作台启动说明](06-m2-workbench.md) 安装、构建并启动 API 与 Runner。重启 API 自动迁移到 `0004`；M3 历史轮次不会被改写。

1. 完成 M3 的当前代码自审后，在“设计、测试与反馈”点击“开始材料阶段”。
2. 生成概要设计，检查内容。需要补充时点击“编辑概要设计”，保存人工新版本及原因；原生成版本保留。
3. 登记主管的评审人、实际时间、结论、意见和证据引用。这是由开发者录入外部结论，不会发消息或替主管批准。
4. 明确性能测试是否需要；待明确时保持阻塞。不需要必须说明原因，需要则生成含指标、目标、负载及用例的性能测试单。
5. 生成功能测试单并检查，必要时编辑用例。材料生成不会创建测试执行记录。
6. 测试实际执行后，选择本次登记用例，填写执行人、时间、环境、实际结果和证据引用。必需用例缺失、未执行、失败或受阻时不能验收。
7. 处理未结反馈，再登记材料阶段验收。此状态尚不等于 M5 全项目交付。
8. “导出当前材料包”生成 ZIP，再下载。历史轮次也可以导出，清单明确标记导出时状态。

页面表单固定打开时的版本；其他操作改变材料后会拒绝旧表单。提交后等待对应任务及新版本同步，再开放下一步。

## 有效性和历史

- 人工修改概要设计会使旧主管决定、性能判断、下游测试材料及测试结果不再适用于当前版本。
- 修改功能测试单后，必须为新版本登记结果；需要性能测试时，相关性能单也需要重新确认。
- 文档意见通过明确的反馈标识绑定新版概要设计，不能靠重复填写旧主管通过绕过。
- 原记录与已导出的包不覆盖。历史包的 `status_at_export` 描述导出时状态，不承诺今天仍有效。
- 反馈、版本、材料及任务结果在同一事务提交。保存材料后任务状态提交失败时，整个事务回滚，不能留下假成功材料。
- SQLite 本地短事务采用显式 `BEGIN IMMEDIATE`，确保保存点参与外层事务；PostgreSQL 先锁需求，再处理流程/材料，避免同需求操作相互等待。

## 反馈回路

| 类型 | 当前行为 |
| --- | --- |
| Bug | 开启新修复轮次；明确勾选“沿用原已确认范围”时从开发开始，保存原范围来源；否则返回分析 |
| 需求变更 | 必须填写新需求正文，保存新修订，再从分析开始 |
| 架构变更 | 保存带架构意见的新修订，从分析开始；不自动当作旧方案已通过 |
| 文档意见 | 当前材料回到概要设计，新版本后重新登记主管评审，代码自审保留 |

上述反馈不会自动提交 Agent 任务。非文档反馈保留为未结项；新代码自审和测试完成后，以当前基线登记“已解决/接受风险”和证据，才能完成材料验收。

## 存储、接口与导出

迁移新增 `material_rounds`、`material_versions`、`material_records`、`material_attempts`、`material_exports`。文档内容和人工记录保存在控制数据库，生成角色只挂载独立代码副本、专属 Agent 主目录及 staging。正式导出目录为数据目录下的 `exports/`，不挂载给 Agent。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/requirements/{id}/materials` | 当前轮次、阶段、材料、记录和执行结果 |
| `GET /api/v1/requirements/{id}/materials?round_id=...` | 读取历史轮次及当前有效性 |
| `POST /api/v1/requirements/{id}/materials` | 绑定已自审代码开启材料轮次，支持幂等 key |
| `POST /api/v1/requirements/{id}/materials/steps` | 生成、人工修订、外部登记、反馈或导出，沿用队列租约 |
| `GET /api/v1/requirements/{id}/materials/versions/{version_id}` | 读取不可变版本 |
| `GET /api/v1/requirements/{id}/materials/exports/{export_id}` | 认证及校验文件、条目摘要后下载 |

单份材料最多 80,000 字符。材料包最多 16 MiB，包含本轮最新设计与测试单、登记历史、需求修订、代码评审报告、测试结果、性能跳过原因和条目 SHA-256。固定文件名避免使用模型指定路径；导出不会覆盖原包。暂不包含全部历史正文、用户源码或外部证据文件，完整交付包由 M5 处理。

OpenCode 1.19.4 支持从 stdin 接收输入。执行器通过管道发送上下文，避免大型材料超过系统单个命令参数限制；传输未完成或没有明确结束事件时不能登记成功。该能力依据固定版本 [run.ts](https://github.com/anomalyco/opencode/blob/v1.19.4/packages/opencode/src/cli/cmd/run.ts) 核实，本轮未新增在线模型推理。
