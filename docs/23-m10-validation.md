## 实际运行

通过真实 API 注册独立样例、固定配置、需求和交付分组，再由实际 Runner 创建 Docker 工作区、执行只读预检、启动 OpenCode 环境和运行独立验收文件。初始源码确实没有完成新需求，固定测试实际执行函数与 HTTP 检查后返回失败；工具通过 TAP 失败记录和退出码确认负例，不将它误当作环境已验收或自动重试。

实际容器尝试修改验收文件被拒绝，外部测试摘要保持一致。随后模型步骤的网络诊断得到代理 403，工具停止在提交模型请求之前，请求日志没有新增模型任务。界面清单保持 `INCOMPLETE`，显示缺少模型、技能、评审和人工记录，桌面与 390 px 手机页面没有横向溢出或脚本错误。

一个单独、明确标记的受控正确实现通过了全部六个固定用例。这项检查验证验收测试能区分正确与缺陷实现，不是 Agent 开发成果，也不计为在线开发或模型评审通过。Node 报告器已固定为 TAP，避免不同版本的默认输出格式影响证据识别。

离线备份恢复到新工作台目录后，原负例记录与未完成验收状态保留，没有自动运行容器、模型或审批。原始样例和固定测试仍在外部验收目录中，不被 Agent 修改；完整私有运行目录为 `.local-data/m10-qa-02/`。

新命令入口安装后可运行。当前环境 `agent-workbench-acceptance doctor` 返回退出码 2 和 `BLOCKED_NETWORK`，只含状态、公开端点及分类，不输出代理凭据、响应正文或原始异常。

## 受控测试

单元测试验证只有成功字段不能证明模型执行，缺少文本、明确结束事件、匹配模型或出现错误时不能满足清单。技能声明不等于技能工具操作；长正文截断后，新的完成元数据仍与结束事件共同核对，已知密码保持脱敏。正向事件和子进程在测试中使用明确的受控夹具，不声称实际调用了在线模型。

请求响应丢失、5xx、未识别资源时不会自动重发；资源核实匹配请求键、需求或实际属性。范围、自审、主管、性能判断、测试执行及材料验收均由推进器暂停给人处理。实际审计 API 不修改流程或人工决定，原有受控完整流程仍显示缺少在线证据。

PostgreSQL 17.11 中相同审计保持业务表摘要不变，不泄露数据库密码；恢复到 SQLite 后仍显示未完成。其 M3/M4 前置和人工业务记录沿用明确标记的受控夹具。控制面演练同时修复了就绪探测：以认证 TCP 查询为准，避免把 PostgreSQL 临时初始化服务当作最终可用服务。
