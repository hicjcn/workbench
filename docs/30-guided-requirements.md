# 需求分步操作指南

新建需求后，详情页显示六步导航和“现在要做”。进度来自后端保存的工作区、开发流程和材料记录，无需手工勾选进度。页面只显示当前阶段的主要操作，完成后自动定位到下一阶段；执行 Agent、生成材料及人工确认仍由你明确提交。

| 步骤 | 当前要做 | 进入下一步的条件 |
| --- | --- | --- |
| 1. 准备环境 | 创建代码副本；固定了运行配置时执行环境预检；启动 Agent 环境 | 副本存在、预检通过（如配置）、环境启动成功 |
| 2. 分析与方案 | 开启流程并配置评审模型与验证命令；运行只读分析；阅读方案并填写范围确认依据 | 当前流程的范围与方案已确认 |
| 3. 开发与验证 | 执行 Superpowers 开发，再执行本轮验证命令；多仓库可使用固定的逐仓库命令 | 开发与全部必需验证成功 |
| 4. 评审与自审 | 逐个模型评审、处置问题；展开差异，填写开发者自审依据 | 本轮代码自审通过 |
| 5. 设计与测试 | 概要设计、主管评审、性能判断、测试单、实际测试登记、反馈处置、材料验收 | 当前代码对应的材料轮次验收通过 |
| 6. 验收交付 | 核对完整流程证据；按团队流程交付，跨项目联调和 ZIP 交付包在“跨项目交付”管理 | 根据团队要求人工核查并完成交付 |

材料验收通过会解锁最后一步，不代表需求已经合并、部署或完成业务验收。核对清单会继续指出缺少的真实执行证据。

## 回看与辅助工具

- 点击已完成步骤可回看结果；“返回当前步骤”继续当前待办。未来步骤不可跳过。
- 需求背景和验收标准位于标题下的折叠区。多仓库需求仍从共同父目录运行，并保留各仓库的差异与验证记录。
- “代码差异与自审记录”保留快照、逐仓库改动和人工确认；评审阶段默认展开。采用开发流程的需求从流程中自审，原手动模式入口保留。
- “执行记录”可随时展开；任务运行时可直接“查看执行记录”或取消。取消会保留已经产生的代码。
- “环境与手动工具”保留启停、预检、构建、验证、应用服务及旧手动任务入口。已开启流程时，可从这里回到分析阶段修订需求或新建流程轮次。

## 失败与变更

任务失败或取消后，页面保留当前步骤并显示原因。先检查日志并处理原因，再明确重新运行；页面不会自动重试。状态为 UNKNOWN 时先“停止并核实”，核实完成前禁用执行。

开发环境已停止时，开发与验证步骤提示“启动环境并继续”，已完成的分析与范围确认保留。已固定运行配置的环境预检需要停止开发环境后进行。

需求修订、代码变化或退回使原流程失效时，导航返回“分析与方案”，可新建轮次。Bug 修复若明确沿用已确认方案，后端可直接创建开发入口轮次，页面会定位到“开发与验证”。材料变化会重新计算当前阶段，旧版本、评审与测试记录仍可回看。

## 验证

```bash
npm test --prefix web
npm run build --prefix web
.venv/bin/python poc/verify_requirement_guide.py --root /tmp/awb-guide-new-run
```

浏览器验收需要 Python Playwright 和 Chromium，可通过 `--chromium` 指定可执行文件。`--root` 必须是尚不存在的专用目录；测试只创建该目录内的 SQLite、样例 Git 仓库和源码副本，最终停止测试 API。

验收使用真实浏览器、认证 API、SQLite 及本机源码副本，受控完成执行队列以验证页面推进、门禁、回看、失败重试、修订失效和手机布局；不调用模型、不启动 Docker，也不宣称产生真实审批或业务测试证据。报告见 [分步界面验收记录](evidence/requirement-guide-report.json)。已有 Docker 验收脚本已适配折叠区和分步导航，本次界面调整未重新执行其 Docker 场景。
