# M5 跨项目交付、资源与恢复操作说明

M5 首轮实现以单机控制面为边界。一个“跨项目交付”关联不同项目的现有需求，保留各项目 M3/M4 流程，按人工确认的顺序独立推进；必要项目、当前评审及材料测试结果必须全部满足后才能生成交付包。

## 实施约定

- 交付范围保存不可变修订，汇总各项目分析，范围确认绑定需求修订及分析版本。必要项目开始开发前检查整体范围确认。
- 联调结果需要填写实际环境、结果、登记人、时间、理由和证据；支持通过、失败、无需联调。结论绑定当前所有必要项目的代码、评审与材料基线，不自动执行外部联调。
- 生成交付包或归档时同时预留全部成员，并按固定顺序锁定工作区、停止运行资源、核实各自实际代码；不只检查页面缓存。
- 完整包含代码快照、完整差异、版本、设计、评审、测试及遗留问题；可选项目必须明确跳过原因。
- 归档后保留代码、快照及证据；重新打开需要明确原因，不自动启动模型任务。
- 同时控制任务领取数量和本控制目录的容器数量；清理只停止已核实属于当前目录的资源，不执行全局 prune。
- 备份/恢复使用维护命令。要求控制服务停止、任务已核实及容器停止；备份保存元数据、独立 Git 工作区、快照及导出证据，排除访问令牌、模型认证、Agent 主目录和临时运行密码。
- 恢复到全新目录，校验清单、路径和摘要，重建访问令牌并重定位工作区；不会覆盖原目录或自动重放任务。恢复后按保存输入开启新会话，不能声称透明恢复 Agent 进程。

本轮验收使用明确标记的样例和受控模型结果。真实用户项目、在线多模型串联、业务依赖数据及生产交付仍需独立验收，不能把功能实现等同于全部 MVP 验收完成。

## 页面使用

1. 在“项目登记”中登记各个 Git 项目，分别创建需求并准备工作区。
2. 在“跨项目交付”中创建交付，按照推进顺序关联项目需求；同一交付每个项目只关联一个需求。最多 8 个成员，至少一个必要成员；跳过成员必须填写原因。一个需求同时只能属于一个活动交付。
3. 各项目先完成只读分析。回到交付页面核对所有分析，登记整体范围确认，然后进入各需求完成 M3 开发、验证、独立评审、自审及 M4 材料、主管登记、测试、反馈和验收。
4. 必要项目全部验收后，完成实际业务联调并登记结果；确实无需联调时明确记录原因。页面登记不会代替外部测试执行。
5. 点击“采集交付包”，填写登记人和证据。Runner 同时预留全部成员，按需求 ID 固定顺序取得文件锁，停止成员及评审运行资源，再核对实际代码与已验收基线。其他成员的任务、修订及代码观察写入会被阻止。
6. 下载 ZIP。包中固定各必要项目的源码、完整 Git 二进制差异、原始版本与当前基线、全部需求修订、流程评审、材料版本、测试登记、反馈记录和联调结论。外部证据保留引用。跳过项目显示 `SKIPPED` 及原因，不标为已测试。包不包含 Agent 主目录和运行密码，也不会推送 Git、合并代码或部署。
7. “归档交付”会再次采集并冻结所有成员的代码操作。重新修改需点击“重新打开”并填写原因。后续需求、代码或材料变化会使原包显示为历史基线；原包仍可下载。

范围修订会使范围确认和联调结论失效。新分析轮次、Bug 修复轮次或需求变更也可能要求重新确认整体范围。成员变更后应检查范围、联调和所有阻塞原因。页面展示的是固定顺序，由人推进；没有自动推断项目依赖或自动跨项目调度。

排队和执行中的交付可取消。租约失效或无法确认全部资源已停止时，操作变为 `UNKNOWN` 并保留全部成员预留。应在交付面板执行“停止并核实全部成员”，完成前不能从某一个成员单独解除预留。所有任务均不会自动重放。

## 资源限制与归属

API 和 Runner 应使用相同数据目录、模型和资源配置：

```bash
export AWB_MAX_ACTIVE_JOBS=2
export AWB_MAX_CONTAINERS=4
.venv/bin/python -m agent_workbench.server --data-dir /path/to/data
# 另开终端，使用同样环境变量
.venv/bin/python -m agent_workbench.runner --data-dir /path/to/data
```

配置范围为 1—32。任务领取在数据库中串行检查执行中数量；容器创建在当前目录的文件锁中检查实际库存，包含开发、只读角色及可核实归属的孤儿容器。一个 Runner 顺序执行任务，可启动多个 Runner 使用同一限额。达到容器限额时停止并给出原因，需先停止不用的环境再明确重试。

“资源与恢复”展示任务数量、磁盘可用量、资源限额及 Runner 最近资源报告。报告按目录过滤，不暴露容器环境变量。报告超过 15 秒显示过期；长任务执行时报告也可能过期，可用维护 `inspect` 获取实际库存。清理只处理当前目录可核实的托管资源，不使用全局 prune，也不删除容器额外挂接的外部网络。

## 离线停止与备份

先停止 API 和所有 Runner。正式 CLI 持有共享维护锁，维护 stop/backup 需要独占锁，服务未停时会拒绝操作。不要在备份期间手动编辑工作区或通过其他程序写入数据库。

```bash
.venv/bin/python -m agent_workbench.maintenance inspect --data-dir /path/to/data
.venv/bin/python -m agent_workbench.maintenance stop --data-dir /path/to/data
.venv/bin/python -m agent_workbench.maintenance backup --data-dir /path/to/data
```

安装更新后的包也可使用 `agent-workbench-maintenance`。`stop` 会核实容器和网络归属、清理运行资源、取消未完成任务并核实代码；代码与证据保留。归属不明时会停止清理，需要检查后重试。

备份必须没有排队、执行、待核实任务、工作区预留或运行容器。输出位于 `DATA/backups/backup_<id>.zip`，命令返回路径、大小和 SHA-256，页面显示已完成验证的备份索引。备份内容包括全部业务表、工作区独立 Git 历史、只读角色副本、控制面工作区清单、快照、材料包和交付包。清单记录每个条目的大小及 SHA-256，并在备份后重新核对代码、元数据和持久文件。

备份排除访问令牌、Runner 令牌、Agent 主目录及认证、临时运行状态、临时输出、已有备份、原始外部仓库和数据库连接配置。沿用源码快照的路径排除规则（如 `.env`、依赖和构建目录）。**备份包含工作区 Git 历史和业务材料，必须私密保存；路径排除不代表能识别源码、历史或用户填写内容中的任意秘密。** 数据库、缓存等业务依赖及其数据需另外备份。

单个归档展开大小上限 512 MiB、条目最多 50,000、清单上限 16 MiB；交付任务固定历史输入上限 16 MiB。超限会报错，不会截断后假称完整。源码初始导出沿用 M1 的 100 MiB 限制。

## 恢复到新目录

```bash
.venv/bin/python -m agent_workbench.maintenance restore \
  --archive /private/path/backup_<id>.zip \
  --destination /path/to/new-data
```

目标必须尚不存在。恢复首先校验 ZIP、路径、清单、展开大小、文件摘要、元数据表及 Git 基线，在临时目录中重建 SQLite，重定位工作区和角色清单，生成权限为 `0600` 的新令牌，校验完成后才发布新目录。不会覆盖原目录、启动容器、恢复 Agent 认证或自动重放历史任务。恢复记录保存在 `restore-info.json`。

SQLite 和 PostgreSQL 的逻辑备份均恢复到新 SQLite 文件。历史任务输入中的旧路径作为审计内容保留，新任务使用重定位后的工作区。原始项目路径保持原值；搬到其他机器时可重复提供 `--project-map prj_<id>=/new/source/path`，映射必须指向现有 Git 根目录。

启动恢复目录前，确保没有继承指向旧数据库的 `AWB_DATABASE_URL`：

```bash
env -u AWB_DATABASE_URL .venv/bin/python -m agent_workbench.server --data-dir /path/to/new-data
# 另开终端，使用相同模型配置；需要模型时重新配置自己的认证
env -u AWB_DATABASE_URL .venv/bin/python -m agent_workbench.runner --data-dir /path/to/new-data
```

使用新目录 `access-token` 登录，检查项目源路径、代码差异、当前评审材料、历史交付包和恢复记录。按当前步骤明确开启新会话；不声称恢复原 Agent 进程或原模型会话。

## 接口和实现入口

`/api/v1/deliveries` 支持列表、创建和详情；`/{id}/revisions`、`scope`、`integration`、`reopen` 保存审计决定；`operations` 排队采集、归档或统一核实；`exports/{export_id}` 校验后下载固定文件。写操作传入读取时的范围或基线摘要，过期表单返回冲突。操作支持请求幂等键。

`GET /api/v1/runtime` 提供资源概要，`POST /internal/runtime` 仅允许 Runner 认证。数据库迁移为 `0005`。交付核心在 `delivery.py`、`delivery_execution.py`、`delivery_export.py`，维护在 `maintenance.py`，通用归档校验在 `checked_archive.py`。

验证结果、复现命令及 AC-01 至 AC-10 的剩余项见 [M5 验证报告](13-m5-validation.md)。
