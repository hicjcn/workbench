# M9 跨项目全景分析

版本 0.9.0，SQL schema 保持 `0006`，无需新增迁移。PR #8 已合并，提交 `62e47a2bb304e496c067e023924412e84784b22c`。本阶段在现有跨项目交付分组上补充联合只读分析，不自动选择仓库或代替人工范围决定。

## 使用流程

1. 登记候选项目，并为各项目创建需求、准备独立工作区。使用固定运行配置的项目，还须先完成其环境预检。
2. 在“跨项目交付”组织候选成员。联合分析覆盖全部成员，包括标为跳过的候选；目前仍需人先登记候选，最多 8 个，每个项目一个需求。
3. 点击“检查全景分析环境”，检查同一容器中所有候选代码是否可读、摘要样本一致且禁止写入。此操作不调用模型、不生成影响结论，也不满足正式范围门禁。
4. 模型已配置且网络可达时，点击“开始联合分析”，填写模型和补充说明。支持现有 OpenCode 显式免费模型或 OpenRouter 显式 `:free` 模型；后者沿用 Runner 的既有环境凭据，不在表单填写密钥。界面的默认模型名不代表已验证其当前服务可用性。
5. 查看逐项目影响、代码证据、项目关系、风险和待确认项。继续完成各项目的分析，再由人确认整体范围；开发、自审、材料和测试继续使用已有流程。

两种操作都会先停止并核实全部成员的开发、应用及旧分析资源，按现有规则保存 PostgreSQL 数据快照，再固定代码副本。数据卷和代码保留。分组之外的需求不参与本次操作。需要保持运行的候选环境应先自行安排停止时机。

## 只读上下文

每次创建独立副本 `attempts/<job>/<requirement>/<project>/repo`，统一只读挂载到一个分析容器：

```text
/workspace/project                  # 第一个成员的分析副本、OpenCode 工作目录
/workspace/candidates/<project-id>   # 每个候选项目的独立副本
```

模型输入明确列出项目 ID、名称、需求内容、容器路径和代码树摘要。容器只看到本次明确登记的候选副本，不挂载原始仓库、其他需求、工作台控制凭据、开发主目录或项目配置文件，不连接开发数据库。代码复制继续排除 `.env`、`credentials` 等固定目录；这不是对任意源码内容的秘密扫描。

OpenCode 权限允许只读工具，其他工具默认拒绝；额外目录权限只覆盖这些候选根目录。源码挂载与容器根文件系统只读，沿用非特权运行及资源限制。多个副本共用一个受管容器名额；有固定配置时使用第一个成员的固定镜像 ID 和资源限额，旧环境沿用登记镜像并记录实际镜像 ID。不会为分析启动业务依赖或应用。

环境检查在容器内读取各候选目录及最多三个短路径文件的摘要样本，并实际尝试写入以确认拒绝；所有副本和源工作区的完整代码摘要在执行前后再次核对。环境通过证明这次可见性与隔离，不证明模型理解了全部代码。

## 报告与确认

真正联合分析要求 OpenCode 返回明确结束事件及结构化 JSON。报告必须恰好覆盖所有候选项目，每个项目标记 `CHANGE`、`NO_CHANGE` 或 `UNCERTAIN`，附摘要；确定的影响结论须有代码证据。项目关系只能引用候选集合中的两个不同项目。

证据路径只能是对应固定代码清单中的普通相对路径。收集时补入文件 SHA-256，检查引用行号没有超出文件；不接受绝对路径、路径穿越、被排除文件或不存在路径。结构错误、项目遗漏、代码变化或缺少结束事件都不能发布有效报告，不自动修复 JSON 或重发模型任务。路径和摘要校验不验证分析语义的正确性，仍须人工审阅。

成功联合报告的 ID 加入整体范围摘要。生成新报告会使原范围决定、联调登记和交付包失效。需求内容变化会使报告不适用；人工确认范围时，联合报告必须对应当前需求与代码。已确认的计划报告保留为当时的分析依据，后续正常开发不要求每改一行都重做全景分析；页面仍显示其代码基线是否变化，代码评审、测试及交付的失效继续由原有规则控制。

未使用联合分析的旧交付保持原门禁；环境检查记录不改变范围摘要。联合分析不会自动完成每个项目的分析节点、改变必要成员、确认范围或解除其他验收条件。已使用联合分析的分组修订范围后，必须针对新范围重新生成报告；旧报告保留在历史中，不能通过修订范围跳过已有全景门禁。

## 接口、取消与恢复

```text
POST /api/v1/deliveries/{id}/panorama
```

请求继承现有操作审计字段 `actor/reason/occurred_at/evidence`，额外字段为：

| 字段 | 含义 |
| --- | --- |
| `kind` | `panorama_check` 或 `panorama` |
| `context_digest` | 当前交付详情 `panorama.context_digest`，绑定候选需求和代码 |
| `model` | 联合分析所用的现有免费模型标识；环境检查使用固定免费配置但不推理 |
| `prompt` | 可选补充说明，最多 8000 字符 |

沿用 `Idempotency-Key`、持久任务和全组预留。执行期间所有候选被占用，不能同时修改范围或提交成员写任务。取消会核实分析资源停止后释放全组；即使取消到达时工作已完成，只要取消已被接受，就不发布新结论。清理不明进入 UNKNOWN，保留全部预留，必须从交付面板“停止并核实全部成员”处理，不自动重放。

报告和环境记录保存在现有交付审计表，以不同类型区分；SQL 表和备份格式不变。普通交付包增加全景历史，离线 v2 备份包含记录及独立源码副本，继续排除模型主目录和运行密码。恢复后不自动运行任务或模型，可查看原有历史；本轮实际验证了 M8 v2 归档兼容。

当前能力是已登记候选项目的联合分析辅助，不是自动发现企业全部仓库、自动跨项目开发调度或自动联调。当前云环境的模型凭据及网络条件未满足在线全流程验证，不能将环境检查记录当作模型实测。
