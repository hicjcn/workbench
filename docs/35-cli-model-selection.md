# 从 Agent CLI 选择流程模型

在需求的“分析与方案”打开“新建流程轮次”，点击“读取模型列表”。Runner 会在当前需求的运行容器内执行已固定 CLI 的“列出模型命令”，解析输出后填充“分析与开发模型”和两个评审模型的下拉框。两个评审模型必须不同；读取列表不发送推理请求。

先启动当前需求环境。列表为空、命令失败或尚未读取时，页面显示原因，不能使用虚构的默认候选创建新轮次。登录或模型配置更改后，可点击“刷新模型列表”。运行配置、镜像或 CLI 绑定变更后需要重新读取。

## 配置命令与输出

“Agent CLI 配置”新增“列出模型命令”，例如：

```text
team-code models
/opt/team/bin/team-code models --json
```

已有 CLI 版本没有该字段时，按版本检查命令的程序路径加 `models` 执行；内置配置使用 `opencode models`。封装的列表子命令不同，可保存 CLI 新版本，停止环境并同步最新配置后再读取。命令按参数执行，不支持 Shell 管道、重定向或字符串插值。

支持每行一个 `provider/model` 标识：

```text
team/analysis-model
team/review-model-a
team/review-model-b
```

也支持 JSON 字符串数组，或带 `id` 和可选 `name` 的对象数组；对象数组可以放在顶层 `models` 或 `data` 字段中：

```json
{"models":[{"id":"team/analysis-model","name":"团队分析模型"},{"id":"team/review-model-a"},{"id":"team/review-model-b"}]}
```

列表命令使用容器原有运行用户、HOME、初始化和凭据。读取时仅在列表子进程中隔离工作台生成的模型筛选配置，避免旧的单模型白名单隐藏其他候选；用户自身的配置与凭据保留。不会修改运行服务的共享配置。命令最长运行 30 秒，输出大小及模型数量有上限，原始 stderr 不写入报告。

## 本轮执行与历史

创建轮次时固定主模型、评审模型及列表对应的 CLI／镜像依据。分析和开发使用所选主模型，评审分别使用所选模型，后续材料生成继承主模型。只读分析与评审仍使用独立副本、固定配置和只读权限。

开发步骤在已有正常开发环境上应用所选模型；需要切换时重建 Agent 容器并等待就绪，保留工作区和 Agent 状态。环境未启动或仍为排障状态时，先正常启动后再执行开发。历史轮次保留原有模型，不随刷新列表或更改默认配置变化。

已有轮次和未传入主模型的旧 API 请求保留原有默认模型规则。新界面从 CLI 返回的目录选择模型，不再把目录模型限定为工作台内置免费模型名称；实际可用性由对应 CLI、账号权限与运行环境决定。

Superpowers 预检仅检查插件配置及技能发现，不再要求镜像携带某个固定提交标签。CLI 自身版本、镜像、Node/Git、命令入口、挂载和控制接口检查继续保留。

## 验证

```bash
.venv/bin/python poc/verify_model_catalog.py --root /tmp/awb-model-catalog-new
```

需要 Docker、server/browser 依赖、Chromium 及新的独立目录。脚本使用受控兼容 CLI，验证真实预检、列表命令、浏览器下拉及本轮分析／开发／评审参数，检查文本、JSON、空列表和刷新失败；不调用真实模型或使用用户凭据。结果见[CLI 模型选择验收记录](evidence/model-catalog-report.json)，结束时清理测试容器与镜像。
